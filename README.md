# 墨境微信小程序
原生微信小程序（TypeScript + Sass）、独立 Vue 管理台、Node.js 22 API 与 SQLite 持久化。

## 本地运行
微信开发者工具打开项目根目录，`miniprogram/` 为小程序目录。开发版使用本机 API；体验版和正式版使用 `miniprogram/deployment.json` 中分别配置的公开 HTTPS 域名，并通过 `wx.login` 登录。手机开发版不能通过 `127.0.0.1` 访问电脑；真机联调应使用可访问的测试 HTTPS 域名并保持微信登录。

```text
cd server
npm run dev
```

```text
cd admin-web
npm install
npm run dev
```

管理台的 Vite 服务代理 `/api` 和 `/admin-api` 至 `http://127.0.0.1:3000`。使用 `MOJING_API_PROXY` 可指定代理目标，`VITE_API_BASE` 可配置管理台客户端 API 地址。开发环境管理员账号是 `admin@mojing.local`，密码由 `DEV_ADMIN_PASSWORD` 设置。
本机开发预览：管理台启动后访问 `/preview/`。它读取实际 WXML、Sass、TypeScript 和 API，用于浏览器布局与交互检查；微信授权、胶囊、安全区及真机表现仍需微信开发者工具验收。

## 页面与能力
- 书城、搜索、详情、书架：真实书库、长短篇筛选、封面、收藏和阅读记录。书城手机两列、平板三列、桌面四列，长篇与短篇分区展示；缺图时使用排版封面，继续阅读只展示当前账号的真实记录。公开书库不依赖登录成功，支持离线缓存、刷新和空状态。
- 阅读器：完整分页目录、当前章定位、逐章阅读、章内位置恢复、自动保存、断网重开已缓存的公开章节、字号行距和三种主题。缓存按服务域名隔离并限制容量，未缓存章节需要联网。
- 分享：作品详情与阅读器支持微信好友、朋友圈，复用已有封面；长篇分享定位到当前章节起点，不包含账号或私人阅读进度。加载失败和未发布内容禁用分享。朋友圈单页模式只读公开内容，不调用登录、书架或进度同步。浏览器开发预览支持系统分享、复制阅读链接及剪贴板受限时的可选中文本弹窗；本机链接仅在可访问当前地址的设备上有效，不是微信小程序码。
- 人物图鉴：读者/创作者视图、按阅读进度解锁人物档案。
- 编辑器：正文版本保存、文本续写/改写/润色任务、结果确认后采用、基础结构检查。
- 管理台：真实服务状态、模型配置、用户角色、审核与审计。
- 书评与讨论：详情页真实五星评分、最新/最热排序、分页、一级回复、点赞、剧透折叠、删除与举报。草稿按 API 环境、账号、作品及主题隔离；提交凭据防止网络重试重复发布。公开浏览不需要登录，发言需要会话。正式环境新内容先审核，管理员在“读者内容”处理待审核内容和举报；开发环境即时发布用于联调。评论、点赞和举报持久化到现有 SQLite，备份包含这些数据。

服务启动时从 `server/src/catalog.mjs` 导入六部完整短篇，从 `server/content/` 导入三部长篇；幂等初始化保留阅读记录和用户作品。正文、封面原图与压缩图分别保存在内容目录、`design-concepts/longform-assets/` 和 `miniprogram/assets/books/`。

## 体验与性能优化（方案 B）
- 书城先显示本地公开书库，短时间内重复进入复用结果；手动刷新重新请求。请求层合并相同 GET，缓存按 API 环境和会话区分，写入操作使旧缓存失效。
- 搜索使用服务端真实作品，输入防抖 280ms，每页 20 条，支持继续加载、错误重试和空结果；较早的慢请求不能覆盖新关键词结果。
- 阅读入口使用聚合接口一次取得作品、目录、当前章和插图，公开正文不等待登录。下一章后台预取，切章复用最近预取结果；后台同步阅读位置时不会打断已经开始阅读的用户。
- 公开阅读插图保存到本机文件，按 API 环境隔离，最多 24 张、12MiB。私有创作图片仅使用短时内存缓存；缓存失败继续使用远程地址。正文缓存继续限制为 36 项、2MiB。
- 书架展示当前账号的真实数据、加载/失败/离线状态，主导航统一跳转。创作页隐藏时停止轮询，工作台只在任务活动期间检查任务；编辑器只更新发生变化的正文块，漫画进度更新节流。
- 创建作品、文本任务和保存版本携带持久提交凭据。超时或网络错误后的相同提交复用凭据，服务端原子保存业务写入和响应，重启后可返回原结果；相同凭据对应不同输入时返回 409。旧客户端不携带凭据仍可使用原接口。

新增接口：`GET /api/works?q=关键词&format=longform&offset=0&limit=20` 返回 `items/total/offset/limit`，页长限定 1–50；不带分页和关键词时保留完整书库返回。`GET /api/works/:id/reader-bootstrap` 返回阅读入口数据，支持 `chapterId`、本地恢复参数及 `public=1`；后者仅允许公开内容且不返回私人进度。写入凭据使用 `Idempotency-Key` 请求头，记录保存在 SQLite 的 `client_operations` 表。

本轮验证和复现命令见 [体验与性能验收记录](artifacts/experience-performance-qa/README.md)。接口和前端改动需要一起加载；运行中的旧 API 进程需在正常发布流程中重启。微信文件缓存、登录、安全区、长时间滚动和低端手机表现仍需开发者工具及真机验收，浏览器回归不代表这些能力已经验证。

## 模型
密钥仅在服务端使用；管理台仅返回脱敏提示。文本支持 OpenAI 兼容 `/chat/completions`，图片支持 `/images/generations` 公网 HTTPS 接口；保留 Tuzi `gpt-image-2` 默认配置，并支持同一供应商添加多个模型。其他供应商的原生协议需要额外适配。连接检查只读取模型列表；供应商未开放 `/models` 时报告无法验证，不视为生成已通过。

文本采用“主模型＋有序兜底＋独立审查”：在“模型接入”中新增多条文本配置，用途选正文生成、监督审查或两者兼用。“默认生成”作为主模型，其余生成配置按兜底顺序由小到大选择；“默认审查”独立指定审查主模型。两个默认互不影响，旧配置仍为正文生成用途，需要明确配置审查用途后才启用监督审查。入队时冻结模型、密钥、顺序及审查配置。生成和审查各最多调用 3 次，仅对 HTTP 409/425/429/5xx 等明确失败切换；超时、网络错误和 HTTP 408 标记结果未知并停止，不默默重复收费。

小说续写、改写、润色和大纲成功后自动监督审查，问题包含位置与修改建议，作者决定是否采用候选；未配置审查或审查失败仍保留已生成内容。每个文本任务最多 6 次模型调用，每日容量按任务计数，实际费用取决于各模型计价。候选与报告绑定内容哈希和创作源版本，正文或设定变化后报告失效；审查中断后重启保留候选，审查标记结果未知且不自动续费。导入章节审阅使用审查配置，建议稿需人工采纳并校验源正文版本。条漫分镜继续使用其原有生成流程，不自动执行小说候选审查。

## 并行生产与条漫
管理台“生产队列”可设置总并发、文本/图片并发、每作品并发、每日任务和队列容量，支持暂停派发、取消排队任务。SQLite 保存任务和入队时的模型快照；重启后继续排队任务，已运行任务标记 `SERVER_RESTARTED`，不自动重试收费请求。采用单个 API 进程和网络请求并发，并非多实例或 CPU 线程池。

“条漫工作室”从短篇正文或长篇的单个章节创建独立原文快照，支持创建漫画本、向同一本追加话目、改编授权记录、画风与角色文字设定、AI 编剧、人工分镜编辑、单格或批量生成、明确重试、图片审核、版本恢复与发布。同一本漫画要求续自同一部小说，公开目录按漫画本聚合并按话序展示。正文审查结果为未知、阻断或严重问题时，生产脚本会阻止接受、图片审核和发布；图片生产脚本以 Tuzi coding `gpt-image-2` 为主模型，默认使用平台已配置的图片兜底链（最多三种模型），并记录每次尝试。原图和 WebP 保存在 SQLite；对白与旁白用确定性排版显示。生成结果若对应旧草稿，会保留供人工采用。已发布内容冻结为独立快照，下架立即关闭公开访问。浏览器访问 `/comics/:id`，`/comics` 按本列出并展开话目；小程序书城的“漫画书库”使用公开漫画系列 API。

《赤潮》连载生产入口支持 `--episode N`，每话状态保存在 `artifacts/comic-platform-production/episode-N/`，第一话沿用根目录。运行 `node scripts/comic-platform-next.mjs --episode 3 --start` 提交平台正文任务；不带动作参数查询该话，正文审核后运行 `--accept-story`。再运行 `node scripts/comic-platform-production.mjs --episode 3 --start` 提交分镜，审核后依次使用 `--accept-storyboard`、`--images`、`--approve-images`、`--publish`。所有审核动作必须先检查实际内容。续写入口省略话数时恢复最新未完成话，或从最新已完成话开始下一话；监督时应指定话数。每话脚本共享排他锁，状态原子保存，重启后从正式队列恢复已提交任务，避免重复提交。锁文件记录 PID，异常终止遗留锁时先核实该进程已停止再清理。正文来源为上一话漫画原文快照，画风及人物档案沿用上一话。入口使用本地正式数据库与运行中的 API，不支持连接另一台服务器。

正文审查发现问题时，可用 `--review-feedback 路径` 提交审查意见，由平台模型修订成功候选；`--retry-writing` 仅用于失败任务。原候选保留在正式队列，两类操作共用每话最多三次写作任务的上限。新话默认仅使用 Tuzi `gpt-image-2`；用户明确允许图片兜底后，可在图片提交时设置 `COMIC_IMAGE_RETRY_POLICY=configured`，该话会保存策略并复用后台顺序。

首版角色一致性依靠固定文字设定与人工审核，没有参考图编辑、跨格一致性保证、自动整书改编、漫画系列卷管理或图片气泡定位。标准图片调用只提交 `model/prompt/n`，供应商的尺寸、质量、参考图参数需后续适配。容量较大时应迁移素材到对象存储；不要启用多个共享此数据库的 API 进程。建议从图片并发 1–2 开始，观察供应商限流、内存和付费账单后再提高。

## 部署
不强制使用微信云开发。单台 Linux 服务器可运行现有 API 和 SQLite；多实例扩容前需要把 SQLite 换为共享数据库，并将生成素材放入对象存储。具体步骤见 `server/deploy/README.md`。仓库根目录的 `compose.yaml` 提供单实例 API、持久化数据卷、Caddy 自动 HTTPS 和管理台部署。
服务器环境变量参考 `server/.env.production.example`，不要提交实际 `.env`、模型密钥或 AppSecret。正式环境关闭开发登录，并校验管理员密码、微信凭据与独立加密密钥。

发布检查：`npm run check`、`npm test`、`npm run check:release`。生产预检发现未填域名或凭据时会以失败退出，不会调用模型或输出密钥。运行检查前在 `admin-web` 执行 `npm ci`。使用 `npm --prefix server run backup` 可生成不覆盖旧文件的已验证 SQLite 在线备份，完整部署与回退要求见部署文档。

分享浏览器回归：环境中有 Playwright 和 Chromium 时运行 `node scripts/share-preview-qa.mjs`；可通过 `PLAYWRIGHT_MODULE_ROOT` 指定其依赖目录、`CHROMIUM_EXECUTABLE` 指定浏览器路径、`PREVIEW_URL` 指定运行中的预览服务。截图保存在 `artifacts/share-qa/`。微信真实分享卡片、朋友圈菜单和接收方打开仍需体验版真机验收。

书城浏览器回归：同一环境下运行 `node scripts/library-preview-qa.mjs`，检查四种宽度的素材、分类、刷新、作品跳转、继续阅读、离线和缺图回退，截图保存在 `artifacts/library-qa/`。首页 PNG 图标来自现有 Lucide 库，使用 `node scripts/build-library-icons.mjs` 可重建，不调用图片模型。

短篇封面原图保存在 `artifacts/cover-originals/`（Tuzi coding `gpt-image-2`，每张一次调用）。`node scripts/build-editorial-covers.mjs` 仅使用原图重建书名/作者排版和 480×720 WebP，不再次调用模型。小程序封面在 `miniprogram/assets/books/editorial/`，详情、书城、搜索、书架和分享复用；导入作品使用自己的已审核封面，缺图显示文字封面。

讨论浏览器回归：运行 `node scripts/discussion-preview-qa.mjs`，截图在 `artifacts/discussion-qa/`。四种宽度验证封面、输入、草稿恢复、评分、发布、点赞、回复、剧透、分页和缺图兜底；使用浏览器请求拦截模拟互动数据，不向实际书库写入测试评论。服务测试使用隔离数据库，另有真实 HTTP 重启持久化和生产审核测试。手机键盘、微信原生弹层与发布仍需体验版真机验收。当前审核为人工审核队列，不等同于已完成微信平台内容安全审核或上线合规审查。
